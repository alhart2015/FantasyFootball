## Phase 1 — the blend (pure, no I/O)

### T1 — expose ESPN's weekly stat line

`src/projections/draft/backtest/espn_weekly.py` already builds the full line in
`_statline_dict` and immediately scores it away. Add a sibling that returns it.

```python
def espn_weekly_statlines(
    payload: dict[str, Any], *, week: int, skill_positions_only: bool = False
) -> pd.DataFrame:
    """One row per player: espn_id, position, + the nine canonical stat fields.

    `parse_espn_weekly` scores the same line immediately; this returns it unscored so a
    blend can average per-stat and score ONCE (see `dfs/blend.blend_statlines`). A player
    with no weekly projection entry is ABSENT, not present at zero — that absence is what
    makes him unstartable downstream, which is how bye weeks work with no bye-week rule.
    """
```

**Tests** (`tests/test_draft/test_espn_weekly.py`, extend):
- a payload with a known weekly entry returns the nine fields with ESPN's values
- a player with no `scoringPeriodId == week` entry is absent from the frame entirely
- `skill_positions_only=False` keeps K and DST (empty `position`), matching `parse_espn_weekly`

**Do not** change `parse_espn_weekly`. It has callers.

### T2 — the blend

New module `src/projections/midseason/start_sit.py`.

```python
@dataclass(frozen=True)
class BlendedPoints:
    points: float
    espn: float | None
    sleeper: float | None
    sources: str          # "both" | "espn" | "sleeper"

def blend_weekly_points(
    espn: pd.DataFrame,
    sleeper: pd.DataFrame,
    id_map: pd.DataFrame,
    *,
    weight_espn: float,
    ruleset: Ruleset,
) -> dict[str, BlendedPoints]:
    """Blend per-stat, score once, key by ESPN id."""
```

Mirror `dfs/blend.blend_statlines`: reindex both sides to the full field set first, so a
field present in only one source still gets its suffix on merge — without that,
`row.get(f"{field}_slp")` silently reads `None` and that source's contribution is dropped.

Sleeper crosswalks `sleeper_id -> gsis_id -> espn_id` through `id_map`. Join is **outer**,
not inner: `dfs/blend` uses inner because it wants only rows both sources priced; here a
one-source player must survive (K and DST are always ESPN-only — `parse_sleeper_weekly`
filters to QB/RB/WR/TE).

**Tests** (`tests/test_midseason/test_start_sit.py`):
- both sources present -> per-stat weighted average, scored once under the ruleset
  (assert against a hand-computed number, not against either source's own total)
- `weight_espn=1.0` reproduces ESPN alone; `0.0` reproduces Sleeper alone
- ESPN-only player -> `sources == "espn"`, `sleeper is None`, points == ESPN's
- Sleeper-only player -> symmetric
- a player in neither is **absent from the dict**, not present at 0.0
- a stat present in one source and absent in the other blends on the weights that
  actually have values (the `dfs/blend` `wsum` rule), it does not treat absent as zero
- a player whose `sleeper_id` is not in `id_map` falls back to ESPN-only rather than
  vanishing (the just-signed-player case `waivers` avoids gsis for)

**Gate.**

## Phase 2 — injuries and slot labels

### T3 — source-independent injury rule

```python
def startable_points(projected: float | None, status: InjuryStatus) -> float | None:
    """Weekly points after the injury rule, or None for unstartable.

    Deliberately NOT `waivers.adjusted_weekly_points`. That takes one
    `source_is_injury_aware` boolean, and a blend of an injury-aware source and an
    unmeasured one has no honest value for it — see spec section 5.
    """
```

- `OUT`, `INJURY_RESERVE`, `SUSPENSION`, `DOUBTFUL` -> `None`
- `QUESTIONABLE` -> `projected * injuries.WEEKLY_MULTIPLIER[QUESTIONABLE]` (0.86 — read the
  constant, never re-type the number)
- otherwise unchanged; `None` in -> `None` out

**Tests:** one per branch, plus `None` passthrough, plus an assertion that DOUBTFUL is
`None` and **not** `0.0` (0.0 fills a slot nobody else is eligible for; `None` does not).

### T4 — label which slot each starter fills

`choose_starters` returns indices in fill order and nothing maps them to a `RosterSlot`.

```python
def label_starter_slots(
    chosen: Sequence[int], roster_slots: Mapping[RosterSlot, int]
) -> list[RosterSlot]:
    """Walk POSITION_SLOTS then FLEX_SLOTS in lockstep with `choose_starters`' fill order."""
```

Re-walk `roster_eligibility.POSITION_SLOTS` then `FLEX_SLOTS` consuming
`roster_slots.get(slot, 0)` each — the same order `choose_starters` fills in. Return is
positional against `chosen`.

**Tests:**
- 1QB/2RB/2WR/1TE/1FLEX/1DST -> labels in exactly that order
- a lineup shorter than the slot list (unfillable slot) labels what exists and stops
- SUPER_FLEX comes after FLEX

Display names (RB1/RB2) are a **presentation** concern — number repeated slots in the CLI,
not here.

**Gate.**

## Phase 3 — the diff and P(right)

### T5 — the lineup currently set

```python
def current_starter_ids(roster: pd.DataFrame) -> set[int]:
    """ESPN player ids currently in a starting slot."""
```

Reuse the existing definition rather than inventing a second one:
`web/views/team_view.py` defines a starter as `bool(slot) and slot not in _BENCH_SLOTS`
where `_BENCH_SLOTS = {RosterSlot.BENCH, RosterSlot.IR}`. **Promote that constant** to
`roster_eligibility` and import it in both places; two definitions of "is he starting"
is exactly the drift this repo keeps paying for.

**Tests:** bench excluded, IR excluded, empty `lineup_slot` (unrecognised ESPN id) excluded,
FLEX included.

### T6 — diff current against optimal

```python
@dataclass(frozen=True)
class Swap:
    start: _Row
    sit: _Row
    gain: float          # lineup points, not pairwise difference
    p_right: float
```

Pair the set difference by position-compatibility, in descending pairwise gain. `gain` is
`lineup_points(optimal) - lineup_points(current)` attributed per swap, **not**
`start.points - sit.points` — the cascade means a 0.2 pairwise edge can be worth 1.2 to the
lineup, and the waiver work already paid for learning that.

**Tests:**
- already-optimal lineup -> empty list (and this is a success, not a failure)
- one straight swap
- **the cascade case**: a WR beating WR2 by 0.2 pushes WR2 to FLEX and the FLEX RB out;
  assert total gain exceeds the pairwise 0.2
- a bye-week starter (`None` points) is always swapped out when a startable bench player exists

### T7 — P(right)

```python
def p_right(
    start: _Row, sit: _Row, params: VarianceParams, *, n_sims: int, rng: np.random.Generator
) -> float:
    """P(the started player outscores the benched one this week)."""
```

**Reuse `performance_variance.sample_weekly_points` with `n_weeks=1`** — do not hand-roll a
Gamma. It carries both components: the lognormal season-mean multiplier (talent uncertainty)
and the per-week Gamma (week-to-week noise). Dropping the first would make `p_right` read
*more* confident than the evidence supports, which is the wrong direction for a number whose
whole job is to say "this is a coin flip."

Adapter to get right, and to comment: `sample_weekly_points` takes **season** means and
divides by `SEASON_GAMES` internally. We hold a **weekly** mean, so pass
`weekly_mean * SEASON_GAMES`.

**Tests:**
- identical means and positions -> ~0.50 (tolerance 0.02 at n_sims=20_000, seeded)
- a large edge -> > 0.90
- monotone: widening the gap never lowers `p_right`
- seeded rng -> reproducible to the digit printed

**Gate.**

## Phase 4 — assemble, CLI, verify

### T8 — the orchestrator

```python
@dataclass(frozen=True)
class StartSitRun:
    week: int
    rows: list[_Row]              # every roster player, blended, labelled
    optimal_total: float
    current_total: float
    swaps: list[Swap]
    weight_espn: float
    notes: tuple[str, ...]

def recommend_start_sit(...) -> StartSitRun:
    """Already-fetched data in, a StartSitRun out. No I/O, no formatting."""
```

Same contract as `build_my_team`: pure, so the end-to-end test can drive it from
ESPN-shaped and Sleeper-shaped payloads through the real parsers. **The seam between ingest
and logic is where the web UI's defects lived** — test through it, not around it.

**Test:** one end-to-end from raw payloads asserting the printed numbers, and one asserting
a player ESPN prices but Sleeper does not still starts.

### T9 — the CLI

`scripts/start_sit.py`, copying `waiver_recommender.py`'s preamble exactly:
`add_league_arguments` -> `resolve_league_target(args)` -> `target.require_league_config()`.
Read `target.*` after the call, never `args.league_id` — `resolve_league_target` deletes the
five attributes off the Namespace by design.

Flags: the five shared, plus `--week` (default: schedule-derived `run.week`),
`--weight-espn 0.5`, `--n-sims 20000`, `--seed 0`, `--data-root`, `--credentials`.

Prices your own roster with `fetch_free_agents(..., statuses=("ONTEAM",), scoring_period=week,
limit=n_teams * (sum(roster_slots.values()) + 2))`. **Not** `DEFAULT_FREE_AGENT_LIMIT` —
sharing that limit silently dropped the waiver tool's own starters from the projections.

**Register in `tests/test_scripts/test_league_cli_defaults.py`'s `PARSERS`.** That dict exists
precisely to catch a fifth tool being added without it.

Exit codes follow `trade_analyzer`: 1 on a resolution failure, 0 on a legitimately empty
report.

## Risks

| Risk | Why it bites | Mitigation |
|---|---|---|
| Sleeper `id_map` coverage is thin | Every unmatched player silently becomes ESPN-only, and the tool quietly degrades to the thing the user said has no value | T10 prints the match rate; if it is poor, that is a finding, not a shrug |
| Blend weight is unmeasured | 50/50 is a guess | Stated as a guess in the spec and on screen; §9 follow-up measures it |
| `p_right` reads as precision | A 57% call invites over-trust | Print it beside the point gain, never alone |
| Sleeper endpoint needs a UA header | Bare `urlopen` returns 403 | Reuse `_fetch_sleeper_weekly`, which already sets it |

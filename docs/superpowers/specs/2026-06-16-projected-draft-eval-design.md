# Projected Draft Eval + Scoring/Size Presets — Design

**Date:** 2026-06-16
**Status:** Design (pre-plan)
**Branch:** `feat/draft-eval-presets` (stacked on `feat/draft-board-ux`)

## 1. Motivation

Two related asks from using the live draft board:

1. **End-of-draft quality readout.** A throwaway script (`_scratch_h2h_proj.py`) showed a *projected-vs-projected* full-league simulation of a completed draft: each MC season-week draws injury (availability) + over/under performance (the variance model), sets the optimal starting lineup for every team, and scores higher-projected-total = win. It produced a per-team regular-season win%, make-playoffs%, bye%, and championship%. This measures **roster quality under our projections** (not projection accuracy — actual-vs-projected is explicitly out of scope). The user wants this promoted to a first-class, tested feature shown in the board when a draft finishes.

2. **Configurable scoring + league size.** The board is hard-wired to a 12-team PPR consensus VORP table. The user wants to pick **scoring mode** (default half-PPR) and **league size** (default 16). These are not cosmetic: half-PPR/standard re-score receptions (changing every pass-catcher's projected points and therefore VORP rankings), and league size changes VORP replacement levels — so each combination needs its **own correctly-scored VORP table**, not a relabeled one.

## 2. Goals & non-goals

**Goals:**
- A **tested `src` module** that runs the projected-vs-projected league simulation for a completed draft and returns per-team {regular-season win%, make-playoffs%, bye%, championship%} (+ mean seed), generalized to any (even) team count.
- A **preset system**: a 3×3 grid of scoring `{half-PPR, full PPR, standard}` × size `{10, 12, 16}`, each backed by a correctly re-scored 2026 VORP table; the **whole draft and the end-of-draft sim run under the chosen preset**. Default **half-PPR / 16-team**.
- Board UI: **Scoring** + **Teams** dropdowns in the sidebar (replacing the free-text VORP/league inputs, with a custom-path escape hatch), and a **"Draft results"** panel rendered on draft completion showing the sim metrics (your team + the league table vs the random-team baseline).

**Non-goals (deliberate):**
- **No actual-outcome scoring.** Projected-vs-projected only; this measures roster quality, not projection accuracy (the real-outcome hero-vs-bots eval already exists for that). Stated so no one "improves" it by adding actuals.
- **No change to draft strategies, VORP math, the scoring layer, or the variance model** — all reused. Pure orchestration + data plumbing + UI.
- **No K/DST** — the consensus projection is skill-only; all presets use a skill roster.
- **No configurable playoff format in v1** — the bracket is fixed (top-6 make it, top-2 bye, reg weeks 1–13, wildcard wk14, semis wk15, championship wks 16–17) at every size. Parameterizing it is future work.
- **14-team and non-{10,12,16} sizes** are out (user-selected grid).
- **The 9 parquet tables are untracked artifacts** (regenerated by a script), like the existing `data/consensus_vorp_2026.parquet` — not committed.

## 3. Chosen approach

**Presets backed by pre-generated tables** (user-selected over on-the-fly generation and sim-only): the dropdowns resolve to a preset = an in-memory `LeagueConfig` (built from a single canonical skill roster + the chosen ruleset + team count) and a pre-generated VORP table path. The whole draft loads the matching table; the sim reads the league's `n_teams`/`roster_slots` and the pool's (correctly-scored) `season_mean_fpts`.

**Canonical skill roster (constant across all 9 presets; only ruleset + n_teams vary):**
`{QB:1, RB:2, WR:3, TE:1, FLEX:1, BENCH:9}` (17-man roster, 8 starters) — matches the user's actual draft (the `league_espn_ppr_12team_skill` shape). No K/DST.

## 4. Preset registry + the 9 VORP tables

- **Registry** (`src/projections/draft/assistant/presets.py`): a pure mapping from `(scoring_key, n_teams)` → `DraftPreset(label, league_config, table_path)`.
  - `scoring_key ∈ {"half", "ppr", "std"}` → `Ruleset.espn_half() / espn_ppr() / standard()`.
  - `n_teams ∈ {10, 12, 16}`.
  - `league_config`: built in-memory via a `_skill_config(ruleset, n_teams)` helper using the canonical roster above (no 9 hand-written JSON files).
  - `table_path`: `data/vorp_2026/{scoring_key}_{n_teams}team.parquet`.
  - Default preset: `("half", 16)`.
- **Generator** (`scripts/generate_preset_vorp_tables.py`): **mirrors the proven `build_draft_basis` path** (`src/projections/draft/backtest/draft_basis.py`), which already does `build_consensus(external, league_config.ruleset) → consensus_to_season_projections → generate_vorp_table` and produced the existing correct half-PPR table — so the ruleset threads through `build_consensus`'s ruleset stamp and `generate_vorp_table`'s ruleset-match guard without surprise. The generator differs from `build_draft_basis` only in: (a) it attaches the **published ESPN+Sleeper `consensus_adp` + `full_name`** from `build_consensus`'s output (the real 2026 market), not Sleeper-only ADP; (b) it loops the 9 presets. For each preset, from the raw 2026 external snapshot:
  1. `external = ExternalProjectionSchema.validate(read_latest_partition(data/raw, "external_projections", season=2026))`.
  2. `consensus = build_consensus(external, ruleset)` — **this is the path that genuinely re-scores the stat line under the ruleset** (the column named `projected_points_ppr` holds points under the *given* ruleset; same path that produced the existing correct half-PPR table). `consensus` carries `consensus_adp` (ESPN+Sleeper blend) and `full_name`.
  3. `season_proj = consensus_to_season_projections(consensus)`.
  4. `table = generate_vorp_table(season_proj, league_config)`.
  5. Merge `consensus_adp` + `full_name` from `consensus` onto the table (gsis_id join), cast `gsis_id` to `_PYARROW_STR`, `VorpTableSchema.validate`, write to the preset's `table_path`.
  - `consensus_adp` and `full_name` are ruleset-independent, so they are identical across the grid; only `season_mean_fpts`/`vorp`/`replacement_fpts` differ by ruleset and size. The same `_merge_consensus_columns` introduced for the board's name fix is reused (sourcing from the re-blended `consensus`, not the published PPR partition).
  - The generator prints a per-preset summary and writes all 9 tables under `data/vorp_2026/`.

## 5. The projected-league simulation module

`src/projections/draft/assistant/league_projection.py` — pure, Streamlit-free, tested. Reuses the existing variance sampler (`performance_variance.sample_weekly_points`) and optimal-lineup fill (`season_value._lineup_points_sampled`, `_availability_mask`, `_bye_indices`) — **no re-implemented scoring**.

- **Calendar (fixed):** `regular_weeks = range(1, 14)`, `wildcard_week = 14`, `semifinal_week = 15`, `championship_weeks = (16, 17)`, `playoff_size = 6`, `byes = 2`.
- **`gauntlet_schedule(n_teams, n_weeks) -> list[list[tuple[int, int]]]`**: a 1-factorization (circle method) of `K_{n_teams}` for even `n_teams`, seating slot 1 as the fixed vertex so it plays slot 2 (wk1), slot 3 (wk2), … cycling; the remaining `n_teams-1` labels pair via `(r+k), (r-k) mod (n_teams-1)` for `k = 1..(n_teams-2)/2`. Week `w` uses round `(w-1) mod (n_teams-1)`. Every team plays exactly one game per week.
- **`team_weekly_points(roster, availability, params, *, n_sims, weeks, roster_slots, rng) -> np.ndarray` `(n_sims, len(weeks))`**: draw variance-model weekly points + availability mask, fill optimal starting lineup per (sim, week). (Promoted verbatim-in-spirit from the scratch helper.)
- **`project_draft(rosters, pool, availability, params, *, league_config, n_sims, rng) -> dict[int, SeatProjection]`**: orchestrates — compute each team's `(n_sims, 17)` weekly points; vectorized regular-season records (weeks 1–13) + points-for via the gauntlet schedule; per-sim seeding by `(wins, points_for)` desc; bracket (top-2 byes skip wk14; wk14 wildcard 3v6 & 4v5; wk15 reseeded semis seed1-vs-lowest-survivor & seed2-vs-other; championship = wk16+wk17 combined). Returns per-seat `SeatProjection(reg_win_pct, make_playoffs_pct, bye_pct, champ_pct, mean_seed)`.
- **Tie rule (matchups + bracket):** higher weekly (or 2-week championship) total wins; an exact tie breaks to the **better seed** (lower seed index / regular-season standing). Continuous variance draws make exact ties ~measure-zero; the rule only fixes the degenerate case deterministically. Standings sort `(wins, points_for)` desc with a stable argsort.
- **Schedule note for `n_teams=16`:** the 13 regular-season weeks use rounds `0..12` of the 15-round factorization (no wrap), so slot 1 faces slots 2–14 (not 15/16) — a realistic partial schedule; every team still plays exactly 13 games. For `n_teams=10` the 9 rounds wrap (weeks 1–9 → rounds 0–8, weeks 10–13 → rounds 0–3).
- **Determinism:** a single seeded `rng`; same seed + rosters → identical metrics.
- `is_rookie` is required by the variance sampler; the pool passed in must carry it (the controller attaches it — §6).

## 6. Controller support

`LiveDraftSession.project_league_outcomes(*, n_sims: int = 2000, seed: int = 0) -> dict[int, SeatProjection]`:
- Reconstructs all `n_teams` rosters from `self.picks` by snake slot.
- Lazily loads availability (`load_store_availability(self.pool, season=self.season, data_root=self._data_root)`, where `self._data_root` defaults to `Path("data")` — the board passes it through `_build_session`, mirroring how the session already loads availability for MC strategies) and attaches `is_rookie` to the pool (reusing `_attach_is_rookie` + `_prior_appearance_gsis`, promoted from `backtest/inputs.py` to a shared util if needed), caching both on the session so repeated calls don't reload.
- Requires `self.is_complete`; raises `ValueError` otherwise (the UI only calls it when complete).
- Delegates to `project_draft` and returns the per-seat map (the UI reads `my_slot` + the full table).

## 7. Board UI

- **Sidebar:** replace the free-text "Consensus VORP parquet" / "League config JSON" inputs with:
  - **Scoring** `selectbox`: Half-PPR (default) / Full PPR / Standard.
  - **Teams** `selectbox`: 16 (default) / 12 / 10.
  - These resolve via the registry to `(LeagueConfig, table_path)`; `_build_session` loads that table + config. A collapsed **"Advanced: custom paths"** expander preserves the old free-text inputs (escape hatch) — when set, they override the preset.
  - `my_slot` max is clamped to the chosen `n_teams`.
- **Draft-complete panel** (`_results_col` / a full-width section, rendered only when `s.is_complete`): a **"Run projected eval"** button (the sim takes a few seconds) → calls `project_league_outcomes` → renders:
  - Your team's four metrics vs the random-team baseline (reg 50% / playoff `6/n` / bye `2/n` / champ `1/n`).
  - The full league table (every team: top-3 names, reg win%, playoff%, bye%, champ%), your row highlighted.
  - Result cached on `session_token` + `n_sims` so it does not recompute on every rerun.

## 8. Edge cases / failure modes

- **Incomplete draft** → the results panel shows "Complete the draft to see projected results" and the button is absent; `project_league_outcomes` raises if called early.
- **Missing preset table** (`data/vorp_2026/{...}.parquet` not generated) → `_build_session` surfaces a clear error naming the file and the `scripts/generate_preset_vorp_tables.py` command.
- **Missing 2026 external snapshot** (no `data/raw/external_projections/season=2026` partition) → the generator's `read_latest_partition` raises; the generator fails loud naming the ingest step (`python -m projections.ingest.external_projections --season 2026`), writing no tables.
- **Pool too thin for a size** (e.g., a required starting position can't be filled at 16 teams) → `generate_vorp_table` already raises "cannot fill"; the generator fails loud for that preset (does not write a partial table).
- **2026 byes absent** (schedules partition not ingested) → `load_store_availability` degrades to no byes (warn); injury Bernoulli still applies — unchanged behavior.
- **Odd/unsupported team counts** → only even {10,12,16} are offered; `gauntlet_schedule` documents the even-`n_teams` precondition.
- **Placeholder-gsis rookies on a roster** → they carry `is_rookie=True` (no prior appearance) and a pool `season_mean_fpts`; the sim scores them fine (the sim uses pool positions, not id_map).
- **Determinism** → fixed seed; the cache key includes `n_sims` so changing it recomputes.

## 9. Testing (TDD)

- **Registry:** `(scoring, n_teams)` resolves to a `LeagueConfig` with the right ruleset + `n_teams` + the canonical skill roster; default is `("half", 16)`; `table_path` matches `data/vorp_2026/{scoring}_{n}team.parquet`.
- **Generator:** on a small synthetic external snapshot, a high-reception player's `season_mean_fpts` is **strictly lower under half/standard than PPR** (guards the re-score-not-relabel bug); the emitted table validates `VorpTableSchema` and carries `full_name` + `consensus_adp`.
- **Sim:** `gauntlet_schedule` validity for n ∈ {10,12,16} (every team plays exactly once per week; slot 1's opponents are slots 2,3,… in week order); bracket correctness (champion is one of the two finalists; the top-2 seeds are absent from the wk14 wildcard); **identical-roster league → each seat's metrics ≈ the uniform baseline** (champ ≈ `1/n`, playoff ≈ `6/n`) within MC tolerance; **determinism** (same seed+rosters → identical metrics); a stronger-roster seat beats a weaker one.
- **Controller:** `project_league_outcomes` reconstructs the right number of rosters, raises on an incomplete draft, returns a `SeatProjection` for `my_slot`.
- **Board (`AppTest` smoke):** the Scoring + Teams dropdowns render with the right options/defaults; on an injected **completed** session, clicking "Run projected eval" renders the panel with a numeric championship % for the hero seat; existing smoke tests stay green.
- **Regression:** full `tests/test_draft` + draft-board smoke green; `mypy src tests` + `ruff` clean.
- **Manual:** generate the 9 tables; in the board, run a half-PPR/16 mock draft to completion and confirm the results panel matches a direct sim run.

## 10. Phasing

- **Phase 1 — data basis:** preset registry + `_skill_config` + `scripts/generate_preset_vorp_tables.py`; generate the 9 `data/vorp_2026/` tables.
- **Phase 2 — sim module:** `league_projection.py` (`gauntlet_schedule`, `team_weekly_points`, `project_draft`, `SeatProjection`) + tests.
- **Phase 3 — controller:** `LiveDraftSession.project_league_outcomes` + tests.
- **Phase 4 — board UI:** sidebar dropdowns (+ custom-path escape hatch) + draft-complete results panel + AppTest smoke.
- **Phase 5 — verify + sync:** generate tables, run a board draft end-to-end, full gates, update PM/TODO.
